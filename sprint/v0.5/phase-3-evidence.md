## Live demo
The sandbox container running at localhost:8080 serves the AIO Sandbox web UI (HTML), NOT the agent-infra/sandbox API. The `/v1/health` endpoint returns 404. The agent-infra/sandbox image (`ghcr.io/agent-infra/sandbox:latest`) is not the same as the AIO Sandbox web UI container currently running on port 8080. Therefore, the live two-call demo cannot be executed in this environment. All session logic is verified through comprehensive mocked tests. The sandbox tool code paths for session scoping (cwd injection, session_id threading) are exercised in `test_react_integration_two_sandbox_calls`.

## ReAct e2e trace
The phase brief references `tests/e2e_smoke.py` which does not exist in this project. The substitute evidence is `test_react_integration_two_sandbox_calls` which verifies:
1. First sandbox call without session_id auto-creates a session and returns session_id in result
2. Second sandbox call with session_id reuses the session
3. Both calls return consistent session_id in the result

This is a unit-level mock test (not a full e2e trace through the ReAct executor). A full e2e trace would require OPENCODE_ZEN_API_KEY and a running agent-infra/sandbox container, neither of which are available.

## Config additions
- `RASPUTIN_OMNITOOL_SANDBOX_SESSION_TTL_MIN` — default 60 (minutes)
- `RASPUTIN_OMNITOOL_SANDBOX_MAX_SESSIONS` — default 10
- `RASPUTIN_OMNITOOL_SESSION_ROOT` — default `~/.rasputin/sessions/sandbox`
All three are plumbed through `agent/config.py` and consumed by `get_sandbox_session_manager()`.

- `manifest.json` — regenerated by `scripts/regenerate-skill-manifest.py` after sandbox manifest changes. This is an automated step required to keep the top-level manifest in sync with tool manifests.

- `tests/test_sandbox.py` — updated to pass `session_id: None` to opt out of sessions where isolation is needed. Required because the sandbox tool now auto-creates sessions by default.
