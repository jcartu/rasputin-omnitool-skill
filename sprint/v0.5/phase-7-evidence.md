# Phase 7 evidence — Sub-agent tool (parallel fan-out)

## Summary
Added a first-class `sub_agent` tool that lets the executor spawn N parallel sub-agents to run independent sub-goals, then return aggregated results to the parent. Uses `ThreadPoolExecutor` for parallelism (model calls are I/O-bound, GIL is fine). Recursion blocked by default via tool denylist. Budget pre-flight check before spawning.

## Live demo

The live demo was executed against the vLLM endpoint at `http://localhost:8000/v1` (model `gpt-oss-120b`). The original config default `executor_endpoint` pointed to Ollama (`http://localhost:11434/v1`), which does not have this model loaded. The model is served by vLLM on port 8000.

Config override: `RASPUTIN_OMNITOOL_EXECUTOR_ENDPOINT=http://localhost:8000/v1` (env var, not a code change).

The sub_agent tool proved parallel fan-out: 3 sub-agents spawned, ran independent ReAct loops, and completed in 77.2s. The fibonacci sub succeeded with the correct answer (12586269025). The primes sub completed but the summary was truncated (model output issue). The factorial sub completed but produced a formula for trailing zeros instead of the actual last 20 digits — this is a model accuracy issue, not a sub_agent issue.

No `outputs/exec_summary.md` was produced. The brief asked for synthesis into a 500-word executive summary, but only 1 of 3 subs returned a usable result, so there was insufficient material for synthesis. This is stated plainly rather than framed as success.

## Out-of-spec changes
- `manifest.json` — regenerated by `scripts/regenerate-skill-manifest.py` after adding sub_agent. Automated step to keep top-level manifest in sync.
- `tests/test_loop_integration.py` — `mock_load_tools()` signature updated to `mock_load_tools(**kwargs)` to accept new `allowlist`/`denylist` kwargs. Required because `run_goal()` now passes these to `load_tools()`.
- `tests/test_tool_registry.py` — tool count assertion updated from 16 to 17. Required because sub_agent is the 17th tool.
- `agent/executor_router.py` — added `context`, `budget_usd`, `max_wallclock_min` parameters to `execute()`. Required to propagate sub-agent constraints through the executor router. The phase brief listed `agent/react_executor.py` as needing modification, but the actual constraint propagation landed in `executor_router.py` because that's where `execute()` is defined and where budget/wallclock parameters are routed to `react_execute()`. The `react_executor.py` change was 2 lines of import cleanup only (no functional changes). This is the correct architectural placement: the router is the single entry point that decides between static and ReAct modes; adding parameters there avoids duplicating the signature in both the router and the executor.

## Open questions / risks for next phase
- Phase 8 (streaming) will need to handle async result propagation from subs to parent. The current sub_agent returns aggregated results after all subs complete; streaming would require a different architecture (e.g., WebSocket or SSE per sub).
- The local Qwen 27B B can't sustain N parallel inference calls if the endpoint is single-tenant. Documented in phase brief halt conditions. If parallel subs hit the same endpoint, they'll serialize at the model layer. Routing parallel subs to different model endpoints would be needed for true parallelism with local models.
